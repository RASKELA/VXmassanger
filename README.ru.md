# VX — мессенджер с двумя режимами

[English version](README.md)

VX — мессенджер, который в каждом браузере автоматически выбирает подходящий способ связи.

## Два режима — один адрес

| Режим | Когда включается | Вход и хранение данных |
| --- | --- | --- |
| **P2P** | Браузер может создать WebRTC `RTCPeerConnection`. | Учётная запись не нужна. Контакты и история остаются в браузере, сообщения идут по зашифрованному WebRTC DataChannel. |
| **Обычный (relay)** | WebRTC недоступен или отключён — например, в обычной конфигурации Tor Browser. | Вход по шестизначному коду из e-mail. Пользователи, чаты и история хранятся на сервере VX. |

Выбор сделан по реальной доступности WebRTC, а не по названию браузера. Поэтому Firefox с Tor-расширением будет использовать P2P, если в нём включён WebRTC. Браузер, где WebRTC заблокирован, автоматически получит обычный клиент.

Чтобы намеренно открыть обычный мессенджер, добавьте `?mode=relay` к адресу VX.

> **Важно о приватности:** relay — это обычный серверный мессенджер, он не имеет сквозного шифрования. Для прямого обмена между устройствами используйте P2P.

## Быстрый запуск

Нужен Node.js 20 или новее. Для входа в relay по почте также необходим SMTP-аккаунт.

```powershell
Copy-Item .env.example .env
npm start
```

Откройте `http://127.0.0.1:3000`. Режим P2P или relay будет выбран браузером автоматически.

## Настройка

Скопируйте `.env.example` в `.env` и заполните значения для своего развёртывания. Файл `.env` игнорируется Git и не должен попадать в репозиторий.

| Переменная | Назначение |
| --- | --- |
| `HOST`, `PORT` | Локальный адрес VX. При публикации через Tor оставляйте `HOST=127.0.0.1`. |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE` | SMTP-подключение для отправки кодов входа. |
| `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | Данные почтового ящика и отправитель. Для Gmail нужен App Password, а не основной пароль аккаунта. |
| `DEV_SHOW_OTP` | Вне изолированной машины разработки оставляйте `false`, иначе код может попасть в ответ браузеру. |
| `ICE_SERVERS` | Необязательная настройка STUN/TURN для P2P-клиентов за NAT. Для продакшена используйте свой TURN-сервер. |
| `TOR_ONLY` | Скрывает необязательные WebRTC-звонки в relay-интерфейсе. На отдельный P2P-клиент не влияет. |

Открывайте его через `http://` в Tor Browser.

VX слушает только loopback-интерфейс. Направьте на него onion-службу Tor:

```torrc
HiddenServiceDir /var/lib/tor/vx_service
HiddenServicePort 80 127.0.0.1:3000
```

Перезапустите Tor и прочитайте созданный файл `hostname` в `HiddenServiceDir`: в нём будет ваш `.onion`-адрес. Открывайте этот адрес через `http://` в Tor Browser. Если WebRTC недоступен, автоматически запустится relay-режим.

## Безопасность

- Не передавайте и не коммитьте SMTP App Password. Если пароль был отправлен в чат, отзовите его и создайте новый.
- Храните `.env`, `tor/torrc.local`, данные Tor и ключи onion-службы только локально.
- Для обычного интернета используйте HTTPS, а для P2P за NAT — собственный TURN-сервер.
- Обновляйте Node.js, Tor и операционную систему.

## Проверка

```powershell
npm run check
```

Команда проверяет синтаксис сервера, загрузчика режимов, P2P-клиента и relay-клиента.
